# v0.3 Release Guide / v0.3 版本說明

## 目標 / Goal

v0.3 turns the project from a DataOps MCP demo into an enterprise data-platform reference with Vertica, multi-source catalog routing, metadata/lineage, parser-based SQL policy, bearer RBAC, and auditability.

## Major capabilities

### Vertica Adapter

- official `vertica-python`
- schema/table/view discovery
- column metadata
- owner/remarks/object type
- projection discovery
- projection-storage row estimate
- view dependency lineage
- guarded `EXPLAIN`
- session-level READ ONLY mode

### Metadata / Lineage

New tools:

```text
get_table_metadata
get_table_lineage
analyze_sql_lineage
```

Catalog lineage and SQL-derived lineage are represented separately to avoid presenting inferred relationships as observed catalog facts.

### SQL Policy

v0.2 used keyword guardrails. v0.3 adds SQLGlot parsing and AST inspection, rejecting write/DDL nodes, `SELECT INTO`, write CTEs, and multiple statements.

### Bearer Auth / RBAC

Streamable HTTP can enable MCP SDK bearer-token validation. Roles map to explicit scopes and every tool enforces the required scope.

### Audit

Every MCP tool/resource/prompt invocation records actor, role, action, result, latency, and safe metadata. SQL is represented by a fingerprint rather than raw text.

### Release safety

GitHub Release automation no longer publishes merely because `main` changed. It waits until both `CI` and `Security` have succeeded for the same commit.

## Upgrade

```bash
git pull
pip install -e '.[dev]'
pytest
ruff check src tests
```

For Vertica:

```bash
export DPMCP_MODE=vertica
export DPMCP_VERTICA_DSN='vertica://readonly_user:change-me@vertica:5433/warehouse?tlsmode=require'
```

For protected HTTP:

```bash
export DPMCP_TRANSPORT=streamable-http
export DPMCP_AUTH_ENABLED=true
export DPMCP_API_TOKENS_JSON='{"replace-me":{"client_id":"catalog-agent","role":"reader"}}'
```

Do not store real token values in `.env.example`, source control, screenshots, or issue content.
